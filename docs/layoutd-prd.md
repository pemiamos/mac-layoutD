# layoutD 产品需求文档

状态：Draft  
日期：2026-06-15  
产品定位：专门为中文科普图书设计的 AI 图文排版系统

## 1. 三行摘要

layoutD 是一款面向中文科普图书创作者、编辑和小型出版团队的 macOS 原生图文排版工具。

它以“长文稳定排版 + 大量图片管理 + AI 版式建议”为核心，帮助用户从 Word、Markdown、图片素材库快速生成可审校、可重排、可导出印刷 PDF 的书稿版面。

第一阶段目标不是复刻 InDesign，而是做出一个能稳定排完一章中文科普样章的垂直工具。

## 2. 背景与问题

中文科普图书通常包含大量图片、图注、侧栏、知识卡片、流程图、对比图、术语解释和跨页展示。传统工具存在明显断层：Word 容易编辑正文，但图文混排、版式一致性和印刷输出较弱；InDesign 专业但学习成本高，对非专业排版用户和中文科普内容生产流程不够友好；AI 设计工具能生成漂亮页面，但缺乏全书级别的确定性重排和印刷级输出。

layoutD 要解决的核心问题是：让中文科普图书的图文排版从“手工拖拽每一页”变成“结构化内容输入、AI 辅助生成版式、排版引擎确定性输出”。

目标用户的一句话需求：

> 我有一章科普书稿和大量图片，希望快速得到专业、统一、可继续修改、可导出 PDF 的图文混排版面。

## 3. 目标用户

### 3.1 核心用户

- 中文科普作者：有 Word/Markdown 稿件和图片素材，希望自己完成样章或全书初排。
- 图书编辑：需要把作者稿件整理成可审校的图文版面，减少与设计师反复沟通成本。
- 小型出版社/工作室：需要低成本、高一致性的科普书排版流程。
- 设计师/排版师：希望 AI 辅助生成候选版式，但最终仍保留专业控制权。

### 3.2 非目标用户

- 以海报、品牌视觉、自由创意设计为主的用户。
- 以杂志广告、多语言复杂出版、商业印刷全流程为主的大型出版机构。
- 需要完整替代 InDesign 插件生态和高级印前流程的专业团队。

## 4. 产品原则

1. 中文优先：排版规则、默认样式、输入流程、检查项都围绕中文科普图书设计。
2. 图文并重：图片不是附件，而是一等内容对象，拥有图注、来源、DPI、裁切、锚点和版式角色。
3. AI 做建议，排版引擎做最终决定：AI 可以生成方案、重组页面、提出优化建议，但最终分页、字体、网格、PDF 输出必须确定、可复现。
4. 全书一致性优先于单页惊艳：样式系统、网格、组件、章节模板比一次性页面生成更重要。
5. 所见接近所得：画布预览必须尽量接近最终 PDF，避免导出时版面大幅漂移。

## 5. MVP 范围

MVP 目标：支持用户导入一章中文科普内容，管理配图，生成 20-30 页图文混排样章，并导出可审阅 PDF。

### 5.1 必须支持

- 创建图书项目，设置开本、页边距、栏数、基线网格。
- 导入 Markdown 或纯文本正文。
- 识别章节标题、小标题、正文、引用、列表、图注占位符。
- 导入图片素材，显示尺寸、格式、分辨率和使用状态。
- 手动建立正文段落与图片之间的关联。
- 基础中文正文排版：段落样式、字符样式、行距、首行缩进、标点禁则、孤行寡行控制。
- 页面画布：分页预览、缩放、页面缩略图、选中页面元素。
- 图片框：等比适配、填充裁切、手动裁切、图注绑定。
- 常用科普组件：知识卡片、重点解释、数据框、时间线/步骤框、图文对照块。
- AI 版式建议：针对当前页面或一组图片生成 2-4 个布局候选。
- 版面审查：检查图片 DPI、缺失图注、图文关系、溢出文本、重复使用图片。
- 导出 PDF，用于审校和样章展示。

### 5.2 暂不支持

- 完整 PDF/X、CMYK、专色和高级印前预检。
- 复杂表格编辑器。
- 竖排书、古籍、繁体专业排版。
- 跨章节自动索引、参考文献管理。
- 多人实时协作。
- 插件市场。
- 完整替代 InDesign 的自由设计能力。

## 6. 核心用户流程

### 6.1 新建项目

用户选择图书类型模板，例如“科普单栏”“科普双栏”“图文百科”“儿童科普”。系统生成默认开本、页边距、字体层级、图注样式、图片网格和章节模板。

### 6.2 导入内容

用户导入 Markdown、纯文本或后续支持的 Word 文件。系统解析标题层级、正文段落、列表、引用和图片占位符，形成结构化书稿。

### 6.3 管理图片

用户拖入图片素材。系统自动读取图片尺寸、DPI、格式、色彩空间和重复图片。用户可以为图片补充图注、来源、版权、关键词和推荐用途。

### 6.4 自动初排

系统根据模板、内容结构和图片关联生成初排页面。正文自动流入页面，图片按图文关系进入图片框，图注与图片绑定。

### 6.5 AI 生成候选版式

用户选中页面、跨页或一组图片，要求系统生成不同策略：

- 图主导：大图优先，文字围绕图片解释。
- 文主导：正文阅读优先，图片作为辅助。
- 对照解释：图片、标注和说明形成并列关系。
- 知识卡片：将局部内容转为边栏或重点框。

AI 输出的是结构化版式建议，由本地排版引擎渲染，不直接生成不可控的静态图片。

### 6.6 人工微调

用户可以调整图片裁切、组件类型、段落样式、页面模板、图注位置和图文锚点。修改后系统重新分页，并尽量保持已确认页面稳定。

### 6.7 检查与导出

导出前系统运行检查：

- 文本是否溢出。
- 图片是否低于目标 DPI。
- 图注是否缺失。
- 图片是否未被使用或重复使用。
- 标题层级是否异常。
- 页眉页脚和页码是否完整。

用户导出审校 PDF。

## 7. 功能需求

### 7.1 文档模型

系统需要内部维护结构化文档，而不是只保存画布坐标。

核心对象：

- Book：项目级信息，包括书名、作者、开本、样式库、素材库。
- Section：章节或部分。
- Story：可流动文本流。
- Paragraph：段落节点，包含样式、内容、锚点。
- Asset：图片素材，包含元数据、使用记录、裁切建议。
- Page：页面实例。
- Frame：文本框、图片框或组件容器。
- Component：知识卡片、图文对照、流程图等可复用组件。
- LayoutPlan：AI 或模板生成的版式计划。

### 7.2 中文排版

MVP 需要实现：

- 中文段落样式：字号、字体、行距、段前段后、首行缩进。
- 标题层级样式。
- 中西文混排空隙规则。
- 行首行尾禁则。
- 标点挤压的基础策略。
- 孤行寡行控制。
- 基线网格。
- 页眉、页脚、页码。

后续增强：

- 更细的标点压缩优先级。
- 脚注。
- 旁注。
- ruby/拼音。
- 竖排。
- 繁体中文区域规则。

### 7.3 图片与图文关系

图片应作为一等对象管理：

- 自动读取尺寸、DPI、格式。
- 显示素材使用状态：未使用、已使用、重复使用。
- 支持图注绑定。
- 支持图片来源和版权字段。
- 支持主体裁切建议。
- 支持图片角色：章节主图、正文插图、边栏图、跨页图、步骤图、对比图。
- 支持图片与段落锚定。

### 7.4 AI 设计辅助

AI 能力应围绕明确任务设计：

- 页面重排：给当前页面生成多个版式候选。
- 跨页设计：为两页展开生成大图、标题和说明的组合。
- 图片裁切建议：基于主体和可读性建议裁切框。
- 组件转换：把一段解释转为知识卡片、步骤框或对比框。
- 风格统一：检查页面是否偏离当前图书设计系统。
- 版面审查：给出可执行修改建议。

AI 输出必须是结构化数据，例如页面网格、组件类型、图片框位置、文本流策略和样式引用，而不是只输出一张设计图。

### 7.5 样式系统

至少包含：

- 正文样式。
- 一级/二级/三级标题。
- 图注样式。
- 引用样式。
- 知识卡片样式。
- 边栏样式。
- 页眉页脚样式。
- 颜色令牌。
- 间距令牌。
- 图片圆角/描边/阴影策略。

样式变更应能影响全书，并触发可控重排。

### 7.6 页面画布

画布需要支持：

- 单页视图。
- 跨页视图。
- 页面缩略图。
- 缩放和平移。
- 选中、移动、调整图片框和组件。
- 显示页边距、栏线、基线网格。
- 溢出文本提示。
- 低分辨率图片提示。

### 7.7 导出

MVP 导出：

- 审校 PDF。
- 页面 PNG 预览。
- 项目源文件。

后续导出：

- 印刷 PDF。
- PDF/X。
- 图片打包。
- 版式报告。

## 8. 设计需求

### 8.1 界面结构

建议采用四区布局：

- 左侧：项目导航、章节树、页面缩略图。
- 中央：页面画布。
- 右侧：属性检查器，包括文本、图片、组件、AI 建议。
- 底部或弹层：素材库、问题检查、AI 候选方案。

### 8.2 视觉风格

界面应偏专业工具，而不是营销网站或娱乐化创作工具：

- 信息密度适中，适合长时间工作。
- 控件克制，重点突出页面内容。
- 使用清晰的图标按钮和工具提示。
- 页面画布与操作面板视觉层级明确。
- 默认主题应支持浅色，后续支持深色。

### 8.3 关键体验

- 用户应能在 10 分钟内完成一个章节项目的创建、内容导入和初排。
- 用户应能清楚知道 AI 修改了什么，并能撤销。
- 用户应能锁定已确认页面，避免后续重排破坏。
- 用户应能从问题检查列表直接跳转到对应页面元素。

## 9. 技术路径建议

### 9.1 客户端

首选 macOS 原生：

- Swift + AppKit 负责桌面应用、画布、文件系统、菜单、拖拽、快捷键。
- SwiftUI 可用于侧边栏、设置页、轻量面板。
- Core Text/Core Graphics/PDFKit 用于早期文本绘制和 PDF 输出。

### 9.2 排版内核

排版内核应独立于 UI，负责：

- 文档模型解析。
- 文本流分页。
- 图片锚定。
- 页面模板应用。
- 中文换行和禁则。
- 组件布局。
- 生成可渲染页面树。

长期可引入：

- HarfBuzz 处理字体 shaping。
- ICU 处理 Unicode 边界、换行和分词。
- 自定义 PDF 输出层或 Skia 作为跨平台渲染后备。

### 9.3 AI 层

AI 层不直接改最终页面文件，而是产生 LayoutPlan：

```json
{
  "target": "spread-12",
  "strategy": "image-led",
  "grid": { "columns": 6, "baseline": 5 },
  "blocks": [
    { "type": "image", "assetId": "img-018", "role": "hero", "gridArea": "1 / 1 / 7 / 5" },
    { "type": "caption", "assetId": "img-018", "gridArea": "7 / 1 / 8 / 5" },
    { "type": "body", "storyRange": "p-120:p-127", "gridArea": "1 / 5 / 8 / 7" }
  ],
  "notes": ["Use image-led layout because the image carries the concept explanation."]
}
```

排版引擎验证 LayoutPlan 是否可行，再渲染到页面。

## 10. 成功指标

| 指标 | MVP 目标 | 测量方式 |
| --- | --- | --- |
| 首次初排时间 | 10 分钟内生成一章样章 | 观察 5 个真实样章任务 |
| 可用页面比例 | 自动初排后 60% 页面无需大改 | 人工标注 |
| 图片问题识别 | 识别 90% 低 DPI 和缺失图注问题 | 对照人工检查 |
| AI 候选采纳率 | 每次生成至少 1 个候选被用户保留 | 操作日志 |
| PDF 导出稳定性 | 30 页样章导出无崩溃、无文本丢失 | 自动测试 + 人工检查 |
| 学习成本 | 新用户 30 分钟内完成一章初排 | 可用性测试 |

## 11. 里程碑

### Phase 0：概念验证

- 定义文档模型。
- 实现简单页面画布。
- 支持 Markdown 导入。
- 支持图片素材导入。
- 实现单栏/双栏正文分页。
- 导出基础 PDF。

验收：能排出 5-10 页中文图文样章。

### Phase 1：MVP 样章

- 支持章节模板。
- 支持图注、知识卡片、图片框。
- 实现基础中文禁则。
- 实现 AI 版式候选。
- 实现问题检查面板。

验收：能排出 20-30 页中文科普样章。

### Phase 2：可用内测

- 支持样式库。
- 支持页面锁定。
- 支持跨页视图。
- 支持更完整 PDF 导出选项。
- 支持 Word 导入的初步方案。

验收：完成一本短书或完整章节集的内测排版。

### Phase 3：专业化增强

- 脚注、旁注。
- 高级中文排版规则。
- 印前检查。
- PDF/X。
- 模板市场或模板库。
- 批量图片管理和素材打包。

验收：小型出版团队可以用于真实项目试生产。

## 12. 主要风险

### 12.1 排版引擎复杂度

分页、图片锚定和中文禁则会相互影响。需要从 MVP 开始建立可测试的 layout engine，避免只靠 UI 拖拽堆功能。

### 12.2 AI 输出不可控

AI 生成漂亮页面不等于可出版。必须限制 AI 输出为结构化 LayoutPlan，并经过排版引擎验证。

### 12.3 PDF 与印刷质量

审校 PDF 容易，印刷级 PDF 难。MVP 先明确只承诺审校 PDF，后续再支持 PDF/X、CMYK、字体子集和预检。

### 12.4 图片版权与素材混乱

科普图书图片数量大，来源复杂。素材库必须尽早支持版权、来源、使用状态和导出报告。

### 12.5 与 InDesign 的边界

如果产品宣传成“替代 InDesign”，会引入过高预期。应强调“中文科普图书 AI 图文排版系统”，以垂直场景取胜。

## 13. 开放问题

1. MVP 是否优先支持 Word 导入，还是先用 Markdown 建立稳定闭环？
2. 第一批目标开本是什么？例如 16 开、32 开、185mm x 260mm。
3. 是否需要从第一版支持跨页大图？
4. 图片素材是否需要内置 OCR、主体检测、自动抠图或标注能力？
5. PDF 导出第一阶段是审校用途，还是必须接近印刷交付？
6. 是否需要支持儿童科普这类更强视觉表现的模板？
7. AI 版式建议是否在本地执行，还是调用云端模型？
8. 项目文件格式是否采用单文件包，还是目录结构？

## 14. 下一步建议

下一步应先做三个设计决策：

1. 确定 MVP 输入格式：建议先支持 Markdown + 图片文件夹，Word 导入放到 Phase 2。
2. 确定第一个样章类型：建议选择 20 页左右、图片密度高、包含图注和知识卡片的中文科普章节。
3. 确定项目文件格式：建议采用目录式项目包，便于素材管理、版本控制和后续自动化。

之后进入技术原型：

- 设计 `layoutd.project` 项目结构。
- 设计结构化文档 JSON。
- 做一个最小页面画布。
- 做 Markdown + 图片的初排管线。
- 做 PDF 导出闭环。
