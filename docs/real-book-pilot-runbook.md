# 真实书稿端到端试跑手册（Pilot Runbook）

> 目的：拿**一本真实的书**走完 导入→灌版→微调→导出 IDML→InDesign 验收 全链，
> 用真实数据逼出 layoutD 的真实痛点（而非凭空补功能）。
> 决策背景见 `.ai/DECISIONS.md`；本手册是一次性试跑的操作权威。

## 角色分工（重要）

- **用户（你）**：选书、备料、确认字体、在 layoutD GUI 里做微调判断、在 InDesign 里开包验收 + 截图反馈。
- **Claude（我）**：跑所有 CLI（导入/灌版/预览/导出）、诊断、记录痛点、修 bug。
- **InDesign / GUI 视觉判断只能你来**（我无录屏权限，渲染对错必须人眼）。

---

## 第 0 步 选书与备料（你）

**做什么**：挑**一本有代表性、但不极端**的真实书稿，准备三样东西。

| 料 | 形式 | 说明 |
|---|---|---|
| 书稿 | Markdown（`.md`）或 Word（`.docx`） | 含：多级标题、正文、图、图注、至少一个表格；可含脚注 |
| 图片 | 一个文件夹 | 书里用到的插图，**RGB**、命名无空格/无冲突 |
| 字体清单 | 一句话 | 书稿正文/标题用到的中文字体名 |

**⚠️ 要点**
1. **先选中等复杂度**：别一上来挑"满版美术 + 竖排诗 + 复杂跨页表"的最难章。先证明主链路通，再加难度。
2. **字体两边都要装**：书稿用的中文字体，**本机（macOS）和 InDesign 都必须装**。缺了 → 预览/InDesign 出豆腐或替代字形。先把字体清单给我，我帮你核对本机有没有。
3. **Markdown 只放一个 frontmatter**：开头一个 `---…---` 元数据块即可。**别用多段 frontmatter**（多段头目前会漏成正文，IMP-1 修复中）。
4. **图片用相对路径、RGB**：CMYK 分色交 InDesign 做，灌版阶段一律 RGB。
5. **挑一章即可**：先跑一章（10–30 页量级），不必整本。

---

## 第 1 步 内容导入 + 首次灌版（我，CLI）

**做什么**：我用 CLI 把书稿导入、确定性灌版，导出**忠实正文流预览 PNG/PDF**。

```bash
# 预览（忠实正文流，不套固定模板，最能看真实灌版效果）
swift run layoutD <书稿.md> <图片目录> --export-png-flow <预览输出目录>
swift run layoutD <书稿.md> <图片目录> --export-pdf-flow ~/Desktop/pilot-preview.pdf
# 同时存一份结构化工程，供后续 GUI 微调
swift run layoutD <书稿.md> <图片目录> --export-project ~/Desktop/pilot.layoutd
```

**⚠️ 要点**
1. **先看 `-flow` 预览，不是 `--export-png`**：后者走固定 demo 模板会丢正文段；`-flow` 才是真实书稿的连续灌版。
2. **DOCX 同样支持**：`.docx` 直接当输入；但 DOCX 的样式映射比 Markdown 粗，复杂排版优先 Markdown。
3. **导入即诊断**：导入若报错或丢内容（标题没识别、表格塌成文字、图没进），**当场记进痛点表**——这就是导入器的真实覆盖缺口。

---

## 第 2 步 预览体检（你看图 + 我读预检）

**做什么**：你肉眼过一遍预览 PNG/PDF；我跑预检 gate。

```bash
swift run layoutD <书稿.md> <图片目录> --validate              # 预检当闸门，列问题
swift run layoutD <书稿.md> <图片目录> --preflight-report ~/Desktop/pilot-preflight.json
```

**你重点看**（截图标注给我）：
- 标题层级对不对、正文有没有溢出/吞字
- 图的位置/大小、图注跟图对没对上
- 表格成型没有、有没有塌成纯文字
- 中西文混排间距、整体疏密

**⚠️ 要点**
1. **预览（CoreText）≠ InDesign 渲染**：预览只是早筛，**最终对错以 InDesign 为准**（本周三个 bug 都是预览/单测看不出的）。
2. **预检 JSON 我来读**：字体缺失、图链断、溢框等结构问题在这步就能抓。

---

## 第 3 步 样式基线（GUI；你操作或我用 computer-use 代操作）

**做什么**：把书的视觉规范变成 layoutD 的样式基线。两条路二选一：

- **路 A（先简单）**：直接用内置默认/章节模板，先把链路跑通，样式后调。
  ```bash
  swift run layoutD <书稿.md> --apply-chapter-template scienceChapter
  # 可选模板：scienceChapter / imageRichChapter / studyGuideChapter
  ```
- **路 B（要还原 Figma 样张）**：在 **layoutD GUI** 里导入 Figma/DTCG 样式（Figma 导入是 GUI 功能，无 CLI）。导入后看**token 绑定率体检**报告。

**⚠️ 要点**
1. **Figma 样张要"结构良好"**：用 Variables / 命名样式，别全是写死值——否则 token 绑定率低、导进来很多散值。导入前后我帮你看绑定率报告。
2. **有损项要确认**：基线网格、中文排版项（避头尾/复合字体）Figma 不一定有，导入界面会让你补值——别跳过。
3. **第一轮建议走路 A**：先用默认样式把全链跑通、把痛点暴露出来，样式精修放第二轮。

---

## 第 4 步 AI 受控变体（我）+ 你挑版

**做什么**：在合规样式框架内，让引擎产几种排布变体，你挑。

**⚠️ 要点**
1. **这是 layoutD 的核心卖点，也是验证最薄的一环**——重点观察：AI 出的变体**合不合规、好不好看、是否页页雷同**。
2. 越框的变体会被合规闸门拒掉并回退——留意有没有"想要的版面被拒"或"出来的太保守"。
3. 你挑中的版我固化进工程。

---

## 第 5 步 人工微调（你，在 layoutD GUI）

**做什么**：打开 `pilot.layoutd`，对不满意的页做微调。

**⚠️ 要点**
1. **走 override，不是自由画**：移动/缩放 frame → 引擎捕获为 override → 其余页确定性重排。
2. **撤销可回退**：undo/redo 在；放心试。
3. **锁页保护美术页**：满版图/扉页等设为锁定，后续重排不打乱它。
4. **记体验**：哪里想调却调不了、哪里反直觉——这就是 P4 微调闭环的真实缺口，**全记进痛点表**。

---

## 第 6 步 导出 IDML（我）

```bash
swift run layoutD <书稿.md> <图片目录> --export-idml ~/Desktop/pilot.idml
# 若要对开跨页：
swift run layoutD <书稿.md> <图片目录> --export-idml ~/Desktop/pilot-facing.idml --idml-facing
```

**⚠️ 要点**
1. **导出前断言闸自动跑**：已知 CJK 渲染搭档规则（排版器/脚注/粗斜/字体引用）违规会**当场报错**，不会带病出包。
2. **图片随包**：置入图复制进 `Links/`、相对路径，**换机不断链**——但 `.idml` 旁边的 `Links/` 文件夹要一起给到 InDesign 那台机器。

---

## 第 7 步 InDesign 开包验收（你）

**做什么**：在 **InDesign 中文版**打开 `pilot.idml`，逐项核对，截图反馈。

**验收清单**（逐条看）：
- [ ] 干净打开，无缺失字体弹窗（缺了说明字体两边没对齐）
- [ ] 中文不豆腐、复合字体中西文各就各位
- [ ] 竖排（若有）方向/分行正确
- [ ] 图都在、图链不红、图注跟图对位
- [ ] 表格是真表格（可选行列），不是死文字
- [ ] 脚注（若有）自动编号、正文在脚注区
- [ ] 动态目录页码对、点导引线连续、可"更新目录"
- [ ] 颜色对、分页干净无空白页
- [ ] 整体到"可微调"程度（不是从零重排）

**⚠️ 要点**
1. **这关只能你做**，且**必须真打开看**——结构测试和预览都测不出渲染对错。
2. 每发现一处不对，**截图 + 一句话**发我，我去 diff/修（必要时用 oracle 比对真值）。
